## 二、详细风险分析

### 1. `settings_source_us_vps` 字符串（低风险）

- **当前状态**：已标注废弃，无代码引用
- **删除影响**：无（无代码引用）
- **删除风险**：低
- **建议**：可安全删除，但建议保留 1-2 个版本后再删除，确保无遗漏引用
- **替代方案**：保留现状（已标注废弃）

### 2. `ModuleDownloaderTest.java.disabled`（中风险）

- **当前状态**：已重命名为 `.java.disabled`，不参与编译
- **删除影响**：无（测试文件，不影响生产代码）
- **删除风险**：中（丢失测试逻辑）
- **建议**：不建议删除，应重写为正确的 Kotlin data class API 后恢复
- **替代方案**：用 Kotlin data class 全参数构造函数 + copy() 方法重写

### 3. `UPDATE_SOURCE_VPS_US` 常量（高风险）

- **当前状态**：已标记 `@Deprecated`，`getUpdateSource()` 自动重定向到 AUTO
- **删除影响**：
  - 如果用户历史选择了 US VPS（SharedPreferences 中存储值 2），删除常量后读取会异常
  - 依赖此常量的代码会编译失败
- **删除风险**：高
- **建议**：不建议删除，至少保留 3-5 个版本确保所有用户迁移到其他源
- **替代方案**：保留 @Deprecated 注解，自动重定向到 AUTO

### 4. `US_BASE_URL` 常量（高风险）

- **当前状态**：已标记 `@Deprecated`，值为空字符串（来自 `SERVER_URL_FALLBACK`）
- **删除影响**：
  - `UpdateChecker` 中仍引用此常量（已移除使用逻辑，但常量定义保留）
  - 删除需同步修改 `UpdateChecker` 代码
- **删除风险**：高
- **建议**：不建议立即删除，待 `SERVER_URL_FALLBACK` BuildConfig 字段删除后一并清理
- **替代方案**：保留 @Deprecated 注解

### 5. `SERVER_URL_FALLBACK` BuildConfig 字段（高风险）

- **当前状态**：保留空值，标注废弃注释
- **删除影响**：
  - `UpdateChecker.US_BASE_URL` 引用此字段
  - `app/build.gradle` 和 `core/update/build.gradle` 中定义此字段
  - 删除需同步修改多个文件
- **删除风险**：高
- **建议**：不建议立即删除，待确认无用户使用 US VPS 后再清理
- **替代方案**：保留空值，标注废弃

### 6. `MODULE_FALLBACK_HOST` BuildConfig 字段（高风险）

- **当前状态**：保留，当 fallback 为空时回退到主源 host
- **删除影响**：
  - `App.java:103` 中 `SecureOkHttpFactory.setHosts()` 引用此字段
  - 删除需同步修改 `App.java` 和 `app/build.gradle`
- **删除风险**：高
- **建议**：不建议删除，此字段在 fallback 为空时回退到主源 host，仍有用途
- **替代方案**：保留现状

### 7. `upload_config_us.json`（低风险）

- **当前状态**：可能存在于 `local_private/vps/` 目录（被 .gitignore 排除）
- **删除影响**：无（US VPS 已下线）
- **删除风险**：低
- **建议**：可安全删除（如存在）
- **替代方案**：保留作为历史记录

## 四、总结

本次任务采用"标注废弃 + 自动重定向"策略，而非直接删除，确保：
1. 向后兼容：历史用户的设置自动迁移到 AUTO 模式
2. 编译安全：所有保留的常量和字段仍可编译
3. 渐进式清理：后续版本可逐步删除废弃项
4. 风险可控：高风险项保留，低风险项可后续清理
