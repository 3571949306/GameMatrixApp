## 4. 中优先级建议

### 4.1 引入 ViewModel/Repository 的最小落地路径

项目已依赖 lifecycle ViewModel、Hilt、Room，但主界面仍主要由 Fragment/Activity 直接驱动状态。建议不要全项目一次迁移，按收益排序：

1. `AiFragment` → `AiViewModel` + `AiRepository`：托管消息列表、模板、历史、收藏、任务执行状态。
2. 更新模块 → `UpdateViewModel`：封装检查更新、下载进度、安装提示，减少 MainActivity/设置弹窗耦合。
3. `ToolsFragment` → `ToolsViewModel`：托管搜索、收藏、最近使用、单双列布局和分区排序。
4. 联机大厅 → `OnlineRoomViewModel`：托管房间码、连接状态、重连状态、聊天消息。

### 4.2 统一线程调度和生命周期释放

**现状**

仍能看到较多 `new Thread()`、`Executors.new*()` 和 `Thread.sleep()`。部分位置已经补了 shutdown，但整体调度策略仍不一致。

**建议**

1. 命名并集中提供线程池：`ioExecutor`、`networkExecutor`、`gameExecutor`、`aiExecutor`，不要只提供一个无边界 cachedThreadPool。
2. Activity/Fragment 局部任务优先使用 lifecycle-aware 方案；Java 侧可先封装 `LifecycleExecutor`，Kotlin 侧用 coroutine scope。
3. 避免 OkHttp 拦截器内 `Thread.sleep` 阻塞 I/O 线程，重试策略应尽量使用 OkHttp 超时、拦截器外调度或 WorkManager。
4. `OkHttpClientProvider.preload()` 的延迟加载应改为 `Handler.postDelayed()` 或 App Startup 后台初始化，不要手写 sleep。

### 4.3 修正文档漂移

文档多且有价值，但当前已经出现事实不一致：

### 二、当前实现分析

**下载目录实现**：`UpdateDownloader.getDownloadDir(Context context)` (line 446-457)
```java
public File getDownloadDir(Context context) {
    File baseDir = null;
    if (Environment.getExternalStorageState().equals(Environment.MEDIA_MOUNTED)) {
        baseDir = context.getExternalFilesDir(Environment.DIRECTORY_DOWNLOADS);
    }
    if (baseDir == null) {
        baseDir = context.getFilesDir();
    }
    return new File(baseDir, "update");
}
```
- 当前使用 `getExternalFilesDir(Environment.DIRECTORY_DOWNLOADS)`，这是应用私有目录，用户无法通过文件管理器直接访问
- 这是用户反馈"找不到 APK"的根本原因

**通知实现**：`UpdateNotificationHelper`
- 通知渠道优先级设为 `IMPORTANCE_LOW`，静默无声音，用户可能忽略
- 进度通知是 ongoing 状态，但没有添加"取消下载"的操作按钮

**安装实现**：`UpdateInstaller`
- Android 7+ 使用 FileProvider，通过 content:// URI 提供安装
- 缺少对下载完整性的双重校验（MD5 + 文件大小）
- 缺少对 APK 安装前预检测机制

2. **builtIn模块不需要dex文件**：当`builtIn=true`时，ModuleAdapter显示"启用"按钮而非"下载"，ModuleManager直接标记已安装。不要为内置模块编译dex文件。
3. **新增模块时先确认代码位置**：如果模块的Activity/Fragment代码在主APK的源码目录中，该模块必须标记为`builtIn=true`。只有代码完全独立于主APK（通过DexClassLoader动态加载）的模块才能设置`builtIn=false`并提供downloadUrl。
4. **上传modules.json前验证**：每次修改deploy/modules.json后，必须同时：(a) 上传到VPS的/var/www/update/modules.json；(b) 如果有非builtIn模块，确保对应dex文件已上传到VPS的/var/www/update/modules/目录。
5. **fileSize和sha256必须真实**：非builtIn模块的fileSize和sha256必须与VPS上实际dex文件一致，不能留空或填0。builtIn模块的fileSize填0、sha256留空。
