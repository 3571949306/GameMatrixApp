# 文档治理规则

> **状态**：当前规则  
> **最后核验**：2026-07-27  
> **适用范围**：GameMatrixApp 的 Markdown 文档、发布说明和开发协作资料。

## 目的

项目同时保留发布记录、审计报告、技术方案、路线图和当前开发资料。它们的用途不同：历史记录不能被当作实时事实，工作树中的实现也不能因为某份旧计划而被误判为“尚未开始”。本规则定义每类信息的权威来源和更新方式。

## 事实层级

发生冲突时，按以下优先级判断：

1. **实现事实**：当前源代码、资源、Gradle 配置、Catalog、测试和 `version.properties`。
2. **当前状态摘要**：[`CURRENT_STATE.md`](CURRENT_STATE.md)，只记录已核验的当前事实与明确的发布门槛。
3. **面向用户资料**：根目录 [`README.md`](../README.md) 与 [`RELEASE_NOTES.md`](../RELEASE_NOTES.md)。它们只说明用户能做什么和已发布版本的变化。
4. **技术参考**：代码 Wiki、模块开发指南、安全/发布/测试文档。它们必须标明最后核验日期，并链接到实现或当前状态摘要。
5. **历史资料**：[`CHANGELOG.md`](../CHANGELOG.md)、日期化审计、路线图、重构计划、`docs/archive/`、`项目审计_2026-06-19/`。它们保留当时的判断，不得被用作当前事实来源。

## 版本语义

- `version.properties` 是唯一的版本号来源。
- `versionCode` 是**当前工作版本**，不等于已对外发布。
- `lastStableVersionCode` / `lastStableVersionName` 是**最近稳定发布版本**。
- 只有在产物、签名、下载地址和发布记录都已验证后，文档才能称某个版本“已发布”。
- 每份当前文档都必须区分“工作版本”“最近稳定版”“历史基线版本”。

## 文档分类

| 分类 | 用途 | 更新要求 |
|---|---|---|
| 当前参考 | 当前能力、架构边界、发布门槛、用户路径 | 与实现变更同一任务更新；不得引用已删除文件为权威来源 |
| 用户文档 | 项目介绍、隐私、权限、更新公告 | 只写用户能理解和会受影响的信息；不写内部路径、构建日志或密钥 |
| 发布证据 | 发布流程、签名、Catalog、真机测试 | 标明验证日期、产物和环境；过期证据保留为历史快照 |
| 路线图/方案 | 未来选择、估算、验收目标 | 开头标注基线日期和版本；实时进度以 `CURRENT_STATE.md` 为准 |
| 历史/审计 | 追溯决策与问题 | 不改写历史结论；可在顶部增加“历史快照”提示和当前状态链接 |

## 语言规范

- **用户文档使用中英双语**：根目录 `README.md`、`RELEASE_NOTES.md` 与 GitHub 面向用户的问题/功能建议模板。中文与英文必须表达相同信息，中文在前。
- **项目自有开发文档使用中文**：当前技术参考、模块/服务端/脚本文档、发布/测试/安全资料、路线图、审计、归档和历史变更记录均以中文叙述。
- **不翻译技术标识符**：代码块、命令、配置键、路径、URL、API、类/函数/字段名、协议名、库名和外部产品名保留原样。
- **不翻译第三方内容**：上游/供应商文档、许可证、虚拟环境依赖、生成报告和工具自带 README 保持原文。
- 统一译法见 [`DEVELOPER_TERMINOLOGY.md`](DEVELOPER_TERMINOLOGY.md)。

## 已删除或不存在的资料

索引、README、发布文档和引用文档不得将不存在的文件标成“必读”“首要真值”或当前证据。若一个文件被主动删除：

1. 不恢复该文件，也不回退删除；
2. 删除或替换失效链接；
3. 将仍有价值的规则收敛到当前参考文档；
4. 在历史文档中保留日期化引用，但不能把它作为执行前提。

## 更新门槛

以下变化必须同步更新当前文档：

- 版本、发布通道、模块目录、Catalog schema/版本或下载/验证链；
- 新增/移除用户可见模块或导航入口；
- 初始安装包预算与预装/按需下载边界；
- 权限、隐私、同步或云端数据流；
- BuildConfig 功能开关默认值；
- 用户必须经过的新手引导、安装、更新、恢复或回滚路径。

以下变化只更新历史资料或 changelog：内部重构、一次性调试、过期计划、已结束测试批次。

## 自动核验

运行：

```bash
python tools/audit_markdown_docs.py
```

该脚本检查当前文档的内部链接、已删除的权威目标、版本声明以及与构建/目录配置的关键一致性。脚本输出是提示，不替代对 APK、模块产物和真机路径的验证。
