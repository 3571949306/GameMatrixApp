## 二、公共网络模块

所有联机游戏共享 `com.gamecenter.app.network` 包：

### 2.1 模块清单

| 模块 | 职责 |
|------|------|
| `RelayHttpClient` | HTTP Relay 通信 + WebSocket URL 生成 |
| `GameSocketServer` | 房主权威服务器（WebSocket 模式） |
| `GameSocketClient` | 客户端连接管理（WebSocket 模式） |
| `LANManager` | 局域网 NSD 服务发现 |
| `RemoteP2PUtil` | 房间码生成与解析工具 |

### 2.2 目录结构

```
com.gamecenter.app.network/
├── RelayHttpClient.java     # HTTP POST + WebSocket URL 构建
├── GameSocketServer.java    # 房主端服务器（WebSocket + TCP + Relay）
├── GameSocketClient.java    # 客户端连接（WebSocket + Relay）
├── LANManager.java          # NSD 局域网服务注册与发现
└── RemoteP2PUtil.java       # 房间码格式化、邀请地址解析
```

## 三、联机架构

### 3.1 主机权威性模型

```
┌─────────────┐    操作请求      ┌─────────────┐
│   客机端     │ ──────────────→ │   房主端     │
│  (Client)   │                 │  (Server)    │
│             │ ←────────────── │             │
│             │   SYNC_STATE    │  唯一权威     │
│             │   + ACK         │  状态源       │
└─────────────┘                 └─────────────┘
```

- **房主是唯一的权威**：所有游戏逻辑在房主端执行和验证
- **客机只负责输入和渲染**：客机发送操作意图，房主验证后广播 SYNC_STATE
- **客机不存储完整游戏状态**：状态由房主下发

### 3.2 状态版本机制

```
房主持有: hostStateVersion (long)，每次广播 SYNC_STATE 时递增
客机持有: clientLastStateVersion (long)，收到 SYNC_STATE 后更新
```

防重复/乱序机制：
- 客机发送操作时携带 `clientStateVersion`（当前已知的最新版本号）
- 房主返回 ACK 携带新的 `stateVersion`
- 客机收到 `SYNC_STATE` 时，如果 `incomingVersion <= clientLastStateVersion`，则忽略并回发 ACK

### 3.3 数据流

```
房主 (Android)                    Relay Server (HK VPS)                    客机 (Android)
     │                                    │                                    │
     │── CREATE_ROOM ─────────────────────►│                                    │
     │◄── roomCode, hostToken ────────────│                                    │
     │                                    │                                    │
     │── WebSocket Connect ───────────────►│                                    │
     │                                    │                                    │
     │                                    │◄── WebSocket Connect ───────────── │
     │                                    │     ?room=ABC123&role=client       │
     │                                    │                                    │
     │◄── JOIN (from client) ─────────────│                                    │
     │── SEAT_ASSIGNED ──────────────────►│── SEAT_ASSIGNED ─────────────────►│
     │                                    │                                    │
     │◄── PLACE_STONE/MOVE/THROW ─────────│                                    │
     │  (房主验证操作)                     │                                    │
     │── SYNC_STATE (3次冗余) ───────────►│── SYNC_STATE ────────────────────►│
     │                                    │◄── STATE_ACK ───────────────────── │
     │◄── STATE_ACK ──────────────────────│                                    │
```

## 四、消息协议

### 4.1 通用消息类型

| 消息类型 | 方向 | 用途 |
|---------|------|------|
| `JOIN` | 客→主 | 加入房间 |
| `SEAT_ASSIGNED` | 主→客 | 分配座位 |
| `SYNC_STATE` | 主→客 | 完整状态同步 |
| `STATE_ACK` | 客→主 | 状态版本确认 |
| `GAME_OVER` | 主→广播 | 游戏结束 |
| `CHAT` | 双向 | 聊天 |
| `PING` / `PONG` | 双向 | 心跳 |

### 4.2 各游戏专用消息

#### 五子棋
```json
// 客机 → 房主
{"type":"PLACE_STONE","x":7,"y":7,"clientStateVersion":5,"actionId":1}

// 房主 → 客机
{"type":"SYNC_STATE","stateVersion":6,"board":[[...]],"currentTurn":1,"winner":-1}
```

#### 围棋
```json
// 客机 → 房主
{"type":"PLACE_STONE","x":4,"y":4,"clientStateVersion":3}
{"type":"PASS","clientStateVersion":3}

// 房主 → 客机
{"type":"SYNC_STATE","stateVersion":4,"board":[[...]],"currentTurn":1,
 "blackCaptures":2,"whiteCaptures":1,"scoreBlack":45,"scoreWhite":40}
```

#### 中国象棋
```json
// 客机 → 房主
{"type":"MOVE","fromRow":7,"fromCol":4,"toRow":5,"toCol":4,"clientStateVersion":3}

// 房主 → 客机
{"type":"SYNC_STATE","stateVersion":4,"board":[[...]],"currentTurn":1,
 "isCheck":false,"isGameOver":false,"winner":-1}
```

#### 石头剪刀布
```json
// 客机 → 房主
{"type":"THROW","choice":"ROCK","clientStateVersion":1}

// 房主 → 客机
{"type":"SYNC_STATE","stateVersion":2,"hostChoice":"PAPER","clientChoice":"ROCK",
 "result":"LOSE","roundScore":"1:0"}
```

## 五、每个游戏的实现差异

### 5.1 房主验证逻辑

| 游戏 | 验证内容 |
|------|---------|
| 五子棋 | 落子位置是否为空、是否轮到该玩家 |
| 围棋 | 落子合法性、提子计算、劫争检查 |
| 中国象棋 | 走法是否符合棋子规则、是否送将、是否将军 |
| 石头剪刀布 | 选择是否合法（ROCK/PAPER/SCISSORS） |

### 5.2 SYNC_STATE 内容

| 游戏 | 同步字段 |
|------|---------|
| 五子棋 | board[15][15], currentTurn, winner |
| 围棋 | board[9][9], currentTurn, blackCaptures, whiteCaptures, scoreBlack, scoreWhite |
| 中国象棋 | board[10][9], currentTurn, isCheck, isGameOver, winner |
| 石头剪刀布 | hostChoice, clientChoice, result, roundScore |

### 5.3 游戏结束条件

| 游戏 | 结束条件 |
|------|---------|
| 五子棋 | 一方连成五子 |
| 围棋 | 双方连续虚手（pass） |
| 中国象棋 | 将死/困毙/认输 |
| 石头剪刀布 | 约定局数完成（如三局两胜） |

## 六、新增联机游戏的步骤

如需为其他游戏添加联机功能：

### 6.1 创建 OnlineActivity
1. 复制任一现有 OnlineActivity 作为模板
2. 修改 `P2P_PREFS`、`PROTOCOL_PREFIX`、`PROTOCOL_LABEL`
3. 实现游戏专属的消息处理逻辑
4. 实现房主验证逻辑
5. 实现 SYNC_STATE 构建和解析

### 6.2 修改原有 Activity
1. 在布局文件中添加"联机对战"按钮
2. 在 Activity 中添加按钮点击事件，启动 OnlineActivity

### 6.3 注册 Activity
1. 在 `AndroidManifest.xml` 中注册 OnlineActivity
2. （可选）在 `GameRegistry.java` 中添加 online 入口

### 6.4 添加字符串资源
在 `strings.xml` 中添加：
- `{game}_online` — 联机模式名称
- `{game}_online_desc` — 联机模式描述

## 七、服务器端

### 7.1 WebSocket Relay 服务器
- **位置**：香港 VPS
- **地址**：`wss://hk-ws.<YOUR_DOMAIN>/ddz-ws`
- **技术**：Node.js + ws 库 + nginx 反向代理
- **功能**：消息转发 + 房间管理 + 客户端路由

### 7.2 房间管理
- 房间码：6 位随机字符串（ABCDEFGHJKLMNPQRSTUVWXYZ23456789）
- 房间命名空间：所有游戏共用同一个 Relay 服务器，通过不同协议前缀区分
- 房间过期：房主断开后自动清理

| 问题 | 严重程度 | 说明 |
