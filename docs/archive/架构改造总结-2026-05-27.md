## 二、实际实现与原始架构决策的差异

### 决策1：RePlugin JAR 不可用 → 桥接层方案

**原计划**：使用 `com.qihoo360.replugin:replugin-host-lib:2.3.4`

**实际问题**：jcenter 已关闭，Maven Central 无此 JAR

**实际方案**：
- 创建桥接类 `com.qihoo360.replugin.RePlugin.java`
- 静态方法 `RePlugin.App.attachBaseContext()` 和 `RePlugin.App.onCreate()`
- 底层委托给 `ModuleLoaderV2`（DexClassLoader 实现）
- **风险**：非官方 RePlugin 实现，Android 15+ 兼容性未验证

### 决策2：内置游戏更新策略 → 仅实现版本号判断

**原计划**：版本号判断 + ClassLoader 优先级兜底

**实际实现**：仅实现版本号判断逻辑

**待补充**：ClassLoader 优先级兜底机制（v1.3）

### 决策3：联机功能模块化 → 按原计划实现 ✅

**原计划**：`:core:online` AAR 公共库

**实际实现**：✅ 完全按原计划实现
- `OnlineManager.java` - 联机管理器（公共接口）
- `RelayClient.java` - WebSocket Relay 客户端
- `RoomManager.java` - 房间管理器
- `MessageProtocol.java` - 消息协议

### 决策4：对标大型团队 → 基础框架已建立

**原计划**：ktlint + detekt + GitHub Actions + 测试覆盖率 > 40%

**实际实现**：
- ✅ 代码规范框架已建立
- ⚠️ CI/CD 流水线待配置
- ⚠️ 测试覆盖率当前 29.3%（目标 > 40%）

## 七、关键决策记录

### 7.1 RePlugin 桥接层设计

**背景**：jcenter 已关闭，Maven Central 无 RePlugin JAR

**方案**：创建桥接类 `com.qihoo360.replugin.RePlugin.java`

**接口**：
```java
public static class App {
    public static void attachBaseContext(Application app, Context base) {
        // 委托给 ModuleLoaderV2（DexClassLoader 实现）
        ModuleLoaderV2.install(app);
    }
    
    public static void onCreate(Application app) {
        // 第二阶段初始化
        ModuleLoaderV2.init(app);
    }
}
```

**风险**：非官方实现，Android 15+ 兼容性未验证（TD-03）

### 7.2 模块商店完整 APK 下载

**背景**：用户需求"商店下载的是完整功能模块（APK/dex），而非解锁密钥"

**方案**：`ModuleDownloadManager.kt` + `ModuleVersionChecker.kt`

**流程**：
1. 从 VPS 获取 `modules.json`
2. 比对内置版本 vs. 商店版本
3. 下载完整 APK 到 `data/modules/`
4. 使用 DexClassLoader 加载

### 7.3 联机功能模块化

**背景**：用户需求"联机功能做成独立公共模块，其他 App 可共同调用"

**方案**：`:core:online` AAR 公共库

**接口**：`OnlineManager.java`（所有游戏模块调用此接口）

**分发**：可选包装层 `feature/online-plugin`（RePlugin 插件）
