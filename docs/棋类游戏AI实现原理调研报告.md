# 棋类游戏 AI 实现原理调研报告

> 调研范围：五子棋（Gomoku）、中国象棋（Xiangqi）等棋类游戏的 AI 实现
> 覆盖：核心搜索算法、评估函数设计、五子棋与象棋的 AI 实现差异、现代 AI 技术（MCTS / 深度学习）
> 撰写日期：2026-07-20

---

## 一、背景与问题定义

棋类游戏在 AI 研究中属于**确定性、完全信息、两人零和博弈**。这三个性质决定了：

- **确定性**：不存在掷骰子等随机因素，状态转移完全由规则确定。
- **完全信息**：双方能看到的棋盘信息完全相同，不存在"暗牌"。
- **零和**：一方所得即另一方所失，不存在双赢。

在此设定下，理论上存在"最优策略"（即博弈论中的极小极大解），AI 的目标就是在有限算力内逼近它。

**复杂度对比（决定算法选型）**：

| 游戏 | 棋盘规模 | 合法局面数（量级） | 分支因子（每步平均走法） |
|------|----------|--------------------|---------------------------|
| 井字棋 | 3×3 | 10³ | 8→递减 |
| 国际象棋 | 8×8 | 10⁴⁷ | ~35 |
| 中国象棋 | 9×10 | 10⁴⁸ | ~40 |
| 围棋（19路） | 19×19 | 10¹⁷⁰ | ~180–250 |
| 五子棋（15路标准） | 15×15 | 10¹⁰⁵ 量级 | ~100+（随进程收窄） |

复杂度随棋盘指数增长，因此**暴力穷举不可行**，必须依赖"搜索 + 评估 + 剪枝"的组合。棋类 AI 的技术演进可概括为三代：

1. **第一代（规则驱动）**：手工评估函数 + Minimax/Alpha-Beta 搜索（1997 年"深蓝"击败卡斯帕罗夫）。
2. **第二代（统计采样）**：蒙特卡洛树搜索 MCTS（2006 年起，攻克围棋）。
3. **第三代（深度学习）**：深度神经网络 + MCTS + 自我强化学习（2016 年 AlphaGo，2017 年 AlphaZero）。

## 二、核心搜索算法

### 2.1 极小极大算法（Minimax）

**原理**：假设双方都采取最优策略。从当前局面（根节点）向下搜索一棵博弈树，树的每一层交替代表己方（MAX，最大化收益）与对手（MIN，最小化己方收益）行棋。叶子节点用评估函数打分，分数自底向上回传：

- MAX 层取子节点最大值；
- MIN 层取子节点最小值。

根节点的最终取值即为"在对手最优应对下，我能保证的最好结果"。

**伪代码**：

```text
function minimax(node, depth, isMaximizingPlayer):
    if depth == 0 or node.isTerminal():
        return evaluate(node)          // 叶子评估

    if isMaximizingPlayer:
        best = -∞
        for child in node.legalMoves():
            val = minimax(child, depth-1, false)
            best = max(best, val)
        return best
    else:
        best = +∞
        for child in node.legalMoves():
            val = minimax(child, depth-1, true)
            best = min(best, val)
        return best
```

**缺陷**：时间复杂度 O(bᵈ)，b 为分支因子，d 为搜索深度。例如象棋 b≈40，d=8 时约需 40⁸ ≈ 6.5×10¹² 个节点，普通算力无法承受。

### 2.2 Alpha-Beta 剪枝（α-β Pruning）

**核心思想**：在 Minimax 搜索中，一旦发现某条分支的评估值**不可能影响最终决策**，立即丢弃该分支（剪枝），无需继续展开。

- **α（alpha）**：MAX 方目前已能保证的最小收益下界。
- **β（beta）**：MIN 方目前已能限制的最高收益上界。
- **剪枝条件**：当 `α ≥ β` 时，当前节点之后的子树对最终决策无影响，直接剪掉。

**伪代码（带剪枝）**：

```text
function alphabeta(node, depth, alpha, beta, isMaximizingPlayer):
    if depth == 0 or node.isTerminal():
        return evaluate(node)

    if isMaximizingPlayer:
        value = -∞
        for child in orderedMoves(node):      // 着法排序很关键
            value = max(value, alphabeta(child, depth-1, alpha, beta, false))
            alpha = max(alpha, value)
            if alpha >= beta: break            // β 剪枝
        return value
    else:
        value = +∞
        for child in orderedMoves(node):
            value = min(value, alphabeta(child, depth-1, alpha, beta, true))
            beta = min(beta, value)
            if beta <= alpha: break            // α 剪枝
        return value
```

**效果与工程优化**：

- 理想情况下（着法已按优劣排序），有效分支因子从 b 降至 √b，搜索深度可**翻倍**而算力不变。
- **着法排序（Move Ordering）**：优先搜索吃子、将军、历史高分着法，能大幅提升剪枝效率——这是象棋引擎（如皮卡鱼 Pikafish、佳佳）的核心优化之一。
- **迭代深化（Iterative Deepening）**：从浅到深逐层搜索，复用上一层结果做着法排序，并支持"时间到即停"。
- **置换表（Transposition Table）**：用 Zobrist Hash 记录已算过的局面，避免重复计算；象棋引擎据此判决"长将/长捉"等循环局面。
- **空着剪枝（Null-Move Pruning）、杀手启发（Killer Heuristic）、历史启发（History Heuristic）**：进一步压缩分支因子。例如"佳佳"引擎通过复合策略将平均分支因子从 6.8 压到 3.2 以下。

## 三、评估函数设计思路

当搜索深度有限、无法到达终局时，必须在叶子节点用**静态评估函数**估算局面优劣。评估函数返回的数值通常从某一方的视角计分（如"红方 +100 表示红方略优一个兵卒"，单位是 centipawn／百分之一子力）。

一个稳健的评估函数是多特征加权和：

### 3.1 子力价值（Material Value）

最基础的成分：清点双方棋子，按类型赋予权重。以下为典型中国象棋引擎的赋值（centipawn 体系）：

| 棋子 | 佳佳引擎 | Simple-Xiangqi 引擎 | 说明 |
|------|----------|---------------------|------|
| 车（Rook/Chariot） | 950 | 600 | 最强攻击子 |
| 炮（Cannon） | 430 | 285 | 隔山打牛，跳吃独特 |
| 马（Knight/Horse） | 420 | 270 | 受"蹩马腿"限制 |
| 士（Advisor） | 200 | 120 | 九宫守卫 |
| 象（Elephant） | 200 | 120 | 不过河 |
| 兵/卒（Soldier/Pawn） | 未过河 100 / 过河 150 | 30 | 过河后价值显著上升 |
| 将/帅（General） | 5000+ | 6000 | 被将死即负 |

> 不同引擎数值体系不同（有以"兵=100"为锚点，也有以"车=1000"为锚点），但相对排序一致：**车 > 炮 ≈ 马 > 士/象 > 兵**，将帅价值最高（一旦丢失即败）。

### 3.2 位置价值表（Piece-Square Tables, PST）

同一兵种在不同格位价值不同。PST 是一张与棋盘同样大小的权重矩阵，编码"好格位 vs 坏格位"。例如：

- **兵的 PST**：越靠近敌方腹地分值越高。某引擎中，兵过河后可达 Rank5 = +32 centipawns（加上基础值 30，总计 62），进入敌方九宫附近更高。
- **车的 PST**：控制中心线、开放线、兵林线加分。
- 红黑双方 PST 通常互为镜像（黑方用 `9 - rank` 索引）。

### 3.3 棋子机动性（Mobility）

计算某方合法着法数量，每步给予小幅加分（如每步 +5 centipawns）。机动性高代表控制力强、腾挪空间大。

### 3.4 王/将安全、协同与战术

- **将/帅安全**：周围是否有士、象保护，是否暴露在外。
- **子力协同**：车马炮的火力覆盖重叠率、牵制链、兑子潜力（"佳佳"引擎引入了"子力协同度"指标）。
- **牵制、双车错、马后炮**等战术权重。

### 3.5 五子棋的评估（模式识别导向）

五子棋没有"子力"概念（棋子价值等同），评估函数完全建立在**棋型（pattern）**识别上，典型按威胁强度分级：

| 棋型 | 威胁等级 | 说明 |
|------|----------|------|
| 连五（XXXX | 立即获胜 | 最高优先 |
| 活四（_XXXX_） | 必胜（两端可成五） | 必须封堵 |
| 冲四（XXXX_ 或 _XXXX） | 一手成五，强迫应对 | 优先级高 |
| 活三（_XXX_） | 下一手可成活四 | 高价值 |
| 眠三、活二、眠二 | 次级威胁 | 用于局面优劣排序 |

五子棋评估本质是**扫描全盘所有连线方向（横/竖/斜）统计棋型并加权求和**。由于"连五即胜"规则简单，评估函数的设计重心从"子力"转移到"威胁链与攻击顺序"。

## 四、五子棋与象棋 AI 实现的主要差异

| 维度 | 五子棋（Gomoku） | 中国象棋（Xiangqi） |
|------|-------------------|----------------------|
| **棋盘与分支因子** | 15×15，前期分支高但随进程收窄 | 9×10，分支较稳定（~40） |
| **评估函数来源** | 棋型模式（连五/活四/活三…）识别，无子力概念 | 子力价值 + PST + 机动性 + 将安全 |
| **胜负判定** | 连成五子即胜，规则极简 | 将死、困毙、长将/长捉违规裁决，规则复杂 |
| **搜索重点** | **威胁搜索（VCF/VCT）**：先搜"必胜/必败"进攻链，再做局面评估 | 深度 α-β + 置换表处理循环局面，开局库/残局库 |
| **置换与对称** | 可大量利用旋转/翻转对称性做数据增强 | 对称利用有限，规则不对称（将帅不能照面） |
| **现代方法应用** | 常被用作 AlphaZero 教学实现（棋盘小、规则清晰、易训练） | 主流仍为 α-β + NNUE（神经评估函数）混合架构 |
| **典型强引擎** | AlphaZero-Gomoku 开源复现、各类启发式 bot | Pikafish（NNUE）、佳佳、象棋旋风等 |

**关键差异总结**：

1. **评估函数构造逻辑相反**：象棋靠"子力 + 位置"的加权，**先有物质再谈形势**；五子棋无物质差异，**纯靠棋型威胁链**判断形势。
2. **搜索目标不同**：五子棋对"一手制胜/送死"极度敏感，因此常采用**威胁优先搜索**（先穷举所有成五/活四可能，再做通用搜索）；象棋则依赖深度 α-β 在复杂子力交换中算清得失。
3. **规则复杂度**：象棋需处理"将帅照面""蹩马腿""炮架""长将判负"等大量约束，搜索与规则裁决模块耦合更深；五子棋规则简单，工程重心在评估与威胁枚举。
4. **现代技术落地**：五子棋因规则简单、状态空间相对可控，是深度学习 + MCTS（AlphaZero 范式）最理想的"验证场"；象棋则因悠久的人类棋谱积累，神经网络多用于**评估函数替代（NNUE）**而非完全端到端。

## 五、现代 AI 技术在这些游戏中的应用

### 5.1 蒙特卡洛树搜索（MCTS）

**适用场景**：当分支因子极大（围棋 ~180）、且难以用简单评估函数判断局面时，传统 α-β 陷入"搜不深"困境。MCTS 用**随机模拟（rollout）**估计局面胜率，并通过 UCB 公式在"探索 vs 利用"间取得平衡。

**四步循环**（每次模拟 = 一轮）：

1. **选择（Selection）**：从根节点出发，按 UCB/PUCT 分数递归选子节点，直到叶子。
2. **扩展（Expansion）**：为叶子节点生成未访问的子节点。
3. **模拟（Simulation/Rollout）**：从新节点用快速策略随机下完至终局，得到胜负结果。
4. **回溯（Backpropagation）**：将结果沿路径回传，更新各节点的访问次数 N 与平均价值 Q（注意：每层价值符号翻转，因对手收益即己方损失）。

**UCB / PUCT 选择公式**（AlphaGo/AlphaZero 采用 PUCT）：

```
UCB(s,a) = Q(s,a) + c_puct · P(s,a) · √N(s) / (1 + N(s,a))
```

- `Q`：该着法的平均价值（利用已知好着法）。
- `P`：先验概率（来自策略网络／启发式，引导探索有希望方向）。
- `√N/(1+N)`：访问越少探索奖励越大。
- `c_puct`：平衡系数（常用 0.8）。

**性质**：Kocsis & Szepesvári（2006，UCT 论文）证明，在无限模拟下 UCT 选择次优动作的概率趋于零；实践中其扩展效率可与 α-β 媲美，却无需人工评估函数。

### 5.2 深度学习 + MCTS：AlphaGo / AlphaZero

**AlphaGo（2016）** 的组合：

- **策略网络（Policy Network）**：输入棋盘，输出各落子点概率分布（"哪些点像人类高手会下的"）。
- **价值网络（Value Network）**：输入棋盘，输出当前局面的胜率（"此局面我赢的概率"）。
- **MCTS 绑定**：用策略网络替代部分随机 rollout 缩小搜索空间，用价值网络直接评估叶子，大幅减少模拟次数。

> 形象比喻：策略网络 = "Lusha"（告诉你职业棋手会怎么下，缩小候选），价值网络 = "Foma"（告诉你某局面最终谁赢的概率）。二者配合 MCTS 做有方向的搜索。

**AlphaZero（2017）的范式升级**：

1. **无需人类棋谱**：完全通过自我对弈生成训练数据。
2. **策略-价值一体化网络**：单一残差 CNN 同时输出策略 π 与价值 v（tanh 压到 [-1,1]）。
3. **复合损失函数**：`L = (z - v)² - πᵀ·log p + c·‖θ‖²`（价值 MSE + 策略交叉熵 + L2 正则）。
4. **数据增强**：利用棋盘旋转/翻转对称性，每条数据扩为 8 条。
5. **温度参数**：训练早期 T=1 充分探索，对弈时 T→0 贪心选访问最多着法。

AlphaZero 在同一框架下统一击败了围棋、国际象棋、日本将棋的顶级引擎，证明"通用自我学习"范式有效。**五子棋**是 AlphaZero 范式最常见的开源复现对象（GitHub 上有 PyTorch/TensorFlow 多版本实现），因其棋盘小、规则清晰、训练快，非常适合学习 MCTS + 深度网络协同。

### 5.3 NNUE：象棋专用的神经评估函数

中国象棋/国际象棋的主流强引擎（如 Pikafish）并未完全抛弃 α-β，而是用 **NNUE（Efficiently Updatable Neural Network，高效可更新神经网络）** 替换传统手工评估函数：

- 仍是 α-β 搜索主干，但叶子节点的评估值由小型神经网络（增量更新，随棋子移动快速重算）给出。
- NNUE 学到子力平衡、王安全、兵形结构等"无数微妙模式"，评估质量远超手工特征，使传统搜索架构在硬件受限下仍能达超人水平。

### 5.4 方法对比一览

| 方法 | 代表 | 评估来源 | 搜索方式 | 是否需要棋谱 | 适用游戏 |
|------|------|----------|----------|--------------|----------|
| Minimax + α-β + 手工评估 | 深蓝、传统象棋引擎 | 人工特征 | 确定性剪枝树 | 否（规则即可） | 象棋、五子棋 |
| MCTS（纯随机 rollout） | 早期电脑围棋 | 随机模拟胜率 | 概率采样树 | 否 | 围棋、五子棋 |
| MCTS + 深度网络 | AlphaGo | 策略/价值网络 | 引导式采样 | 是（监督预训练） | 围棋 |
| MCTS + 自我强化 + 单网络 | AlphaZero | 自学习网络 | 引导式采样 | 否 | 通用（含五子棋） |
| α-β + NNUE | Pikafish | 神经网络（增量） | 确定性剪枝树 | 否（自对弈训练） | 象棋类 |

## 六、实践选型建议

- **做象棋类引擎**：α-β 搜索（含迭代深化、置换表、着法排序）+ 手工/PST 评估起步；追求强度时引入 NNUE 替代评估函数。规则裁决模块（长将/长捉、照面）需单独实现。
- **做五子棋引擎**：评估函数以棋型模式库为核心 + α-β（或带 VCF/VCT 威胁优先搜索）；若要体验前沿，可直接复现 AlphaZero-Gomoku（CNN + MCTS + 自我对弈），训练成本低、见效快。
- **重视可解释性**：传统 α-β + 评估函数每一步都能给出"为什么"，适合教学与复盘；深度学习类模型是黑箱，强但难解释。
