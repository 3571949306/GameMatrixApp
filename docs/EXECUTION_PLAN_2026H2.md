## 总体节奏

5 个阶段，约 5–6 个月。核心思路：先解锁模块商店地基（签名 / catalog），再做“安装前可理解 + 云端可信任”，再做首次体验与跨模块连续性，最后做 AI 上下文化与健康连续性。

| 阶段 | 主题 | 周期（估） | 优先级 | 覆盖建议 |
|---|---|---|---|---|
| P0 | 地基与解锁 | 2–3 周 | P0 | 4, 6, 12, 26–28（维护） |
| P1 | 商店体验与隐私卡 | 4–6 周 | P0/P1 | 10, 11, 23, 24, 25 |
| P2 | 首次体验与跨模块连续性 | 6–8 周 | P1 | 7, 8, 9, 14, 15 |
| P3 | AI 作为上下文协作 | 4–6 周 | P1/P2 | 16, 17, 18 |
| P4 | 健康连续性与模块生态 | 6–8 周 | P2 | 13, 19, 20, 21, 22 |

依赖关键路径：P0 的签名 / catalog 修复是后续一切模块商店体验的前置；P3 依赖 P1 的 consent 组件和 P2 的“打开方式”契约；P4 的模块认证清单依赖 P1 的详情 / 隐私卡。

## P1 - 商店体验与隐私卡（4–6 周）

**目标**：安装前可理解；任何云端调用可信任、可取消。

**工作项**

- **#10 按结果组织模块**：catalog `storeCategory` + UI 分组为“娱乐与对战 / 学习与整理 / 阅读与浏览 / 文本与创作 / 设备与网络”。技术交付类型（APK / ZIP / Web / Asset / Unity / Flutter）不再向用户暴露。
- **#11 模块详情必填 + 隐私卡**：体积、权限、离线能力、数据去向、兼容性、更新 / 卸载影响；隐私卡含本地数据、云端数据、网络域、同步位置、保存期限、删除方式。与 #23 共用数据模型。
- **#23 数据与连接中心 v1**：已授权权限、已启用联网模块、最近同步、下载记录、缓存 / 本地数据、一键导出 / 删除。
- **#24 云端调用前明示**：AI / OCR / 同步统一 consent 组件——发送什么、为什么、可否本地、费用 / 网络、如何取消。
- **#25 WebDAV 同步成熟**（可并行，独立于商店）：初次配置引导、连接测试、最近同步结果、可读冲突选择、凭据加密（替换当前 Base64）、本地备份兜底。

**验收**

- 用户安装前能看到全部必填信息与隐私卡。
- 任意云端调用有可取消的 consent，且可改用本地路径。
- WebDAV 首次配置 ≤3 步；冲突可读、可恢复。

## P2 - 首次体验与跨模块连续性（6–8 周）

**目标**：新用户 60 秒内进入目标能力；任务可跨模块流转。

**工作项**

- **#7 意图驱动 onboarding**：首次进入选择“玩 / 学习 / 浏览 / 创作 / 连接”，可跳过。
- **#8 首页聚焦**：首页 = 继续上次任务 + 符合意图的下一步；模块管理移到次页。
- **#9 底部导航服务意图**：已有排序 / 隐藏（最大 6 项，游戏大厅强制保留），加“意图预设”一键应用导航配置。
- **#14 跨模块平台契约**：统一 最近 / 收藏 / 集合 / 打开方式 / 导出 / 备份 / 恢复。定义小而稳的接口，而非每模块各做一套。
- **#15 统一打开方式接入**：
  - 网页 -> 阅读 / 翻译 / 摘要 / 保存到知识库
  - 图片 -> OCR / 整理 / 复习卡 / 导出笔记
  - 错题 -> 识别 / 归类 / 解释 / 安排复习
  - 游戏 -> 复盘 / 提示 / 难度建议 / 可分享战绩
  - 工具 -> 解释结果 / 下一步建议

**验收**

- 新用户首次会话进入目标能力的比例提升；首次模块安装后成功打开比例可测。
- 从一个模块结果进入另一模块完成任务的链路可用（至少 3 条链路）。

## P3 - AI 作为上下文协作（4–6 周）

**目标**：AI 在用户已有内容和意图上减少操作，而非新开聊天页。

**工作项**

- **#16 上下文动作入口**：在网页 / 图片 / 错题 / 游戏 / 工具的结果处提供 explain / summarize / OCR / translate / review / assist。
- **#17 AI 调用统一披露**：复用 P1 的 consent——数据来源（本地 / 云端）、模型、费用、网络 / 隐私、可取消、结果去向。
- **#18 结果作为可编辑草稿**：不自动执行；可编辑、可导出、可保存到对应模块（错题 / 收藏 / 笔记）。

**验收**

- 至少 3 个上下文 AI 动作可用且可取消。
- AI 结果可编辑、可导出、可保存为学习 / 收藏内容。

---

## P4 - 健康连续性与模块生态（6–8 周）

**目标**：进度感不靠压力；新模块接入可预测。

**工作项**

- **#19 挑战改为可选旅程**：可暂停、替换、关闭（基于工作树已有的每日挑战 / 连胜）。
- **#20 回放复盘强化解释**：棋类复盘给“好棋 / 失误 / 漏算”标注（基于已有 `GameReviewAnalyzer` / `replay`）。
- **#21 排行榜优先个人 / 可控范围**：默认个人历史，不制造不透明全局竞争（基于已有 `LeaderboardActivity`）。
- **#22 难度建议可解释可调整**：基于已有 `DifficultyRecommender`，永远允许手动选择。
- **#13 模块认证清单**：依赖 P1 详情 / 隐私卡 + P0 签名稳定。要求模块具备——价值、权限最小化、无障碍、中英文、生命周期、回滚语义、导航贡献、数据导出。

**验收**

- 用户关闭任何挑战 / 提醒后仍能正常使用核心功能。
- 新模块按认证清单接入；至少 1 个新模块走完认证流程。

## 明确不做（guardrail）

- 不做行为追踪 / 广告 / 强制连胜换留存（#3）。
- 不在 WebDAV 同步成熟前引入账号体系（#25）。
- 不在模块认证清单成熟前承诺“第三方模块生态”（#13）。
- 不为追求极小首包把首次必需能力拆成额外下载（#4 / #6）。
- 不把 AI 做成独立聊天页主路径（#16）。
- 历史路线图 / 审计保留为日期化快照，不删不改写（#26–28）。

## 度量（替代“增长至上”指标）

- 首次模块安装后成功打开率。
- 安装前必填信息完整度（隐私卡覆盖率）。
- 云端调用取消率与“改用本地”比例。
- WebDAV 同步冲突解决完成率。
- 跨模块任务完成链路数。
- 用户主动关闭提醒 / 挑战后留存变化。
- 模块更新 / 回滚成功率。

---

## 执行约束

- 遵循 `AGENTS.md` Prime Directive：不回退用户或无关改动；工作树常为脏。
- 任何用户可见改动必须安装到真机 / 模拟器并走真实入口，运行后检查 logcat `FATAL EXCEPTION`。
- 涉及签名 / Catalog / 模块加载的改动，必须以真实产物验证，不能仅凭 Gradle 成功。
- 每个阶段完成后更新 `CURRENT_STATE.md` 的“已核验能力”与“当前发布门槛”。
