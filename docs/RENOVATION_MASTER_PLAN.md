## 0. 改造纲领与原则

**一句话纲领**：以「修冲突、补签名、立 Token」为 MVP 地基，沿「安全 → 架构收敛 → 性能/体验 → AI/兼容」分期推进，始终坚持**无广告、本地优先、渐进迁移**，把 P0 阻断项转化为相对 TapTap/好游快爆的「隐私干净」差异化护城河。

**铁律（来自项目哲学与既有文档）**
1. 渐进式改进，不一次性大重构；收束复杂度而非堆功能。
2. 新页面优先 Compose，现有 XML 页面逐步迁移（不重写）。
3. 以 `version.properties` 为唯一版本事实源。
4. 任何改造不得回退质量基线：14 单测 + 145 UI 自动化全过、Lint 基线只减不增、CI/Dependabot 0 告警。
5. 设计 Token 单一真源，layout 永不直接写 hex/dp。

## 2. 分期推进计划

### 🟢 MVP（本轮必做，约 12 人周）— 地基与信任
| 项 | 痛点 | Effort | 验收要点 |
|----|------|--------|----------|
| A1 暗色冲突修复 | P0-6 | 2 人周 | 切换暗色无 `values`/`values-night` 同名冲突；颜色取自唯一主题源 |
| S1 签名者校验 | P0-5 | 4 人周 | 模块安装前除 SHA-256 外校验签名者证书链，不匹配则拒装并提示 |
| A2 设计 Token | P1-1 | 6 人周 | 语义色/间距/圆角 Token 单源；新增布局强制引用 token，Lint 拦截硬编码 |

> MVP 依赖链：A1 → A2 → 全部美术UI；S1 是 F1 收敛后模块安全的前置。

### 🟡 一期（MVP 之后）— 架构收敛 + 体验 + 质量
- F1 双层模块框架收敛（v2 moduleloader 唯一加载器 + v1 CompatShim 过渡）
- U1 冷启动优化（Macrobenchmark + 内置 Baseline Profile）
- U2 免登录上手（交互式 Coachmark 新手引导，斗地主/围棋）
- U3 模块下载可靠性（重试/校验）
- S2 密钥加固；P2–P5 质量项（Lint 压缩 / 状态机测试 / Socket 拆分 / kapt→ksp）
- P1-2 i18n 中英漏覆盖补全（CI 拦截缺失）
- Android 16/17 深化（edge-to-edge、预测返回、响应式）持续进行

### 🟠 二期及以后 — AI / 兼容 / 个性化
- F2/F3/F4/F5（错题本增强 / 本地 LLM 助手 / 本地发现 / 云存档）
- A4 动态取色；C1/C2 多 ABI 与低端机稳定（权衡 ROI）
- G2 反馈通道

### 🔴 立即立项跟踪（不阻塞 MVP，但须排期）
- **W1 MediaPipe 16KB 页对齐**（架构判最高风险）：跟踪上游 / 本地 source build(`-Wl,-z,max-page-size=16384`) / 换 ONNX·llama.cpp 三路并行 + 运行时降级守卫。影响 F3 本地 LLM 助手落地。

### 3.2 待决 / 缺口（需你拍板或补强）
1. **⚠️ Compose 试点页范围不一致**
   - 架构锁定试点 = **2 页**（设置 + AI 对话，控回归面）
   - 设计标 **5 页**高优先级（游戏大厅、模块商店、设置、AI 对话、新手引导）
   - **我的建议**：Phase 1 试点设「设置 + AI 对话」2 页（与架构一致，稳守 145 UI 用例基线）；大厅/商店/引导列 Phase 2 首批迁移。请你确认。
2. **⚠️ PRD 风险登记漏列 MediaPipe 16KB（W1）**
   - 架构判其为**最高风险**（16KB 页设备加载本地 LLM 的 `.so` 即 `SIGBUS` 崩溃，真实用户会崩），PRD 风险表未体现。
   - **处理**：已在上文 §2「立即立项跟踪」补入 W1，并标注其阻塞 F3。建议纳入风险登记册顶级。
